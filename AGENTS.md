# AGENTS

1. Read `README.md`, `docs/project-context.md`, and `docs/operating-model.md` before changing this repository.
2. Keep this repository a lightweight intake front door, not a duplicate execution backlog.
3. Route known work to the repository that owns delivery.
4. Preserve intake context on the parent issue and implementation detail on native sub-issues.
5. Prefer GitHub issue types, issue fields, Projects fields, and native parent/sub-issue relationships over label-based state machines.
6. Keep labels sparse and reserved for exceptional signals or automation triggers.
7. Do not infer security, privacy, payment, or customer-impact facts that are not supported by evidence.
8. Treat `apt-principles-agents` as the source of truth for reusable APT standards and distribution.
9. Validate issue forms and documentation links before claiming completion.
